Comparing Pre-trained torchvision Models on a Tom & Jerry Image Classification Dataset

Task: classify each cartoon frame into one of four classes based on which characters appear:

ClassMeaningFolder
neitherNeither Tom nor Jerry visibletom_jerry_0
tomOnly Tom visibletom
jerryOnly Jerry visiblejerry
bothTom and Jerry both visibletom_jerry_1

Approach: ImageNet has no Tom/Jerry classes, so the pre-trained models cannot be used for inference as-is. Each model is used as a frozen feature extractor (its ImageNet weights are untouched), and a small linear classification head is trained on the extracted features. This isolates the quality of each architecture’s learned representation and keeps the whole comparison cheap enough to run on a free Colab GPU or even a CPU.

Models compared (5): ResNet-50, DenseNet-121, MobileNetV3-Large, EfficientNet-B0, ViT-B/16.

3. Custom PyTorch Dataset and DataLoaders¶

TomJerryDataset reads a dataframe of image paths and labels, loads each image as RGB, and applies a transform. Each torchvision model ships with its own preprocessing recipe (weights.transforms()) specifying resize size, crop size, interpolation, and normalization, so a separate dataset/loader set is built per model.

class TomJerryDataset(Dataset):
    def __init__(self, dataframe, transform=None):
        self.paths = dataframe["path"].tolist()
        self.labels = dataframe["label"].tolist()
        self.transform = transform

    def __len__(self):
        return len(self.paths)

    def __getitem__(self, idx):
        img = Image.open(self.paths[idx]).convert("RGB")
        if self.transform is not None:
            img = self.transform(img)
        return img, self.labels[idx]

def make_loaders(transform, batch_size=64, num_workers=0):
    mk = lambda d: DataLoader(TomJerryDataset(d, transform), batch_size=batch_size,
                              shuffle=False, num_workers=num_workers,
                              pin_memory=(DEVICE.type == "cuda"))
    return mk(train_df), mk(val_df), mk(test_df)

5. Feature extraction (inference through the frozen backbones)¶

All backbone weights are frozen and run in eval() mode under torch.no_grad(). Features are cached to disk so re-runs are fast. The time per image is recorded as an inference-cost measure.

@torch.no_grad()
def extract_features(backbone, loader):
    backbone.eval()
    feats, labels = [], []
    for x, y in loader:
        feats.append(backbone(x.to(DEVICE)).float().cpu())
        labels.append(y)
    return torch.cat(feats), torch.cat(labels)

FEATURES, INFER_MS, PARAMS_M = {}, {}, {}

6. Train a linear classification head on each set of features¶

A single nn.Linear layer on standardized features, trained with Adam and cross-entropy loss. The epoch with the best validation accuracy is kept. Because the data is mildly imbalanced, class weights are used.

def train_head(feats, epochs=200, lr=1e-3, wd=1e-4):
    Xtr, ytr = feats["train"]; Xva, yva = feats["val"]
    mu, sd = Xtr.mean(0), Xtr.std(0) + 1e-6
    Xtr, Xva = (Xtr - mu) / sd, (Xva - mu) / sd
    Xtr, ytr, Xva, yva = Xtr.to(DEVICE), ytr.to(DEVICE), Xva.to(DEVICE), yva.to(DEVICE)

    counts = torch.bincount(ytr, minlength=len(CLASS_NAMES)).float()
    cw = (counts.sum() / (len(CLASS_NAMES) * counts)).to(DEVICE)

    head = nn.Linear(Xtr.shape[1], len(CLASS_NAMES)).to(DEVICE)
    opt = torch.optim.Adam(head.parameters(), lr=lr, weight_decay=wd)
    lossf = nn.CrossEntropyLoss(weight=cw)

    best_acc, best_state = -1, None
    for ep in range(epochs):
        head.train()
        perm = torch.randperm(len(Xtr), device=DEVICE)
        for i in range(0, len(Xtr), 128):
            idx = perm[i:i+128]
            opt.zero_grad(); lossf(head(Xtr[idx]), ytr[idx]).backward(); opt.step()
        head.eval()
        with torch.no_grad():
            acc = (head(Xva).argmax(1) == yva).float().mean().item()
        if acc > best_acc:
            best_acc, best_state = acc, {k: v.clone() for k, v in head.state_dict().items()}
    head.load_state_dict(best_state)
    return head, mu, sd, best_acc

7. Evaluation on the held-out test set¶

@torch.no_grad()
def predict(name):
    head, mu, sd, _ = HEADS[name]
    X, y = FEATURES[name]["test"]
    logits = head(((X - mu) / sd).to(DEVICE))
    return y.numpy(), logits.argmax(1).cpu().numpy()

Results, Analysis and Conclusion¶

Key findings¶

1. The models are closer than they look. All five models land between 82.7% and 84.9% accuracy. With 822 test images, the 95% margin of error on a single accuracy figure is roughly ±2.6 points, so the gap between the best and worst model is about the size of the noise. ViT-B/16 is the best in this run, but the ranking among the other four (DenseNet, EfficientNet, ResNet, MobileNet) is not statistically reliable. A different random split could reorder them.

2. Model size did not translate into proportional gains. ViT-B/16 has 86.6M parameters, about 16x more than MobileNetV3-Large (5.5M), yet it gains only about 2 points of macro-F1. DenseNet-121 (8.0M) beat the larger ResNet-50 (25.6M) on all four metrics, and the two smallest models (EfficientNet-B0 at 5.3M and MobileNetV3-Large at 5.5M) finished within 0.01 F1 of ResNet-50. Past a certain point, extra capacity gave diminishing returns on this task. In terms of accuracy per parameter, DenseNet-121 and EfficientNet-B0 were the most efficient.

3. ViT’s advantage is most plausibly explained by its pre-training and global attention. Self-attention lets ViT relate regions across the whole frame, which helps when deciding whether a character is present anywhere in the image. ViT also had the highest validation accuracy (0.889), so its edge was visible on two separate splits. Its recall was the strongest for the both class (0.889), but its precision there was low (0.754), meaning it tends to over-predict both.

4. Character-level view: Jerry is harder than Tom. Collapsing the four classes into “Is Tom present?” and “Is Jerry present?” gives F1 scores of 0.905-0.931 for Tom and 0.856-0.877 for Jerry across all models. Jerry is much smaller on screen, is often partly hidden, and has a brown colour that blends into many backgrounds, while Tom is large and distinctively blue-grey. This ordering was the same for every architecture, so it points to the data, not a weakness of any one model.

5. Hardest and easiest classes. Averaged across the five models, per-class F1 was lowest for both (0.795), followed by neither (0.814), jerry (0.833) and tom (0.870). both is the hardest because it needs two small objects detected at once and is the smallest class (780 images, 14% of the data), so it is easily confused with tom or jerry. EfficientNet-B0 struggled most here (F1 = 0.748). Contrary to the initial expectation, neither was not the easiest class: the empty-scene class is likely confused with frames where a character is small, partly hidden, or cut off at the edge by the center crop, so that the character is present in the original frame but missing from the model’s input. (Inspect the error gallery in section 8 to confirm this.)

6. Validation-to-test drop. Every model scored about 3-4 points lower on the test set than on the validation set (for example ResNet-50: 0.880 validation vs 0.829 test). Choosing the best epoch on the validation set makes the validation score slightly optimistic, so the test figures are the honest ones to report.

Possible reasons for the performance differences¶

  • Architecture: ViT-B/16’s global attention and large-scale pre-training gives the most transferable features. DenseNet’s dense feature reuse keeps early colour/edge information available to the classifier, which suits cartoon frames with flat colours and strong outlines. ResNet-50’s residual features were good but not better than the much smaller DenseNet’s. EfficientNet-B0 and MobileNetV3-Large compress their representations (depthwise convolutions, small channel widths), which costs a little accuracy, especially on the small and hard classes (both, jerry).

  • Complexity vs. suitability: the task is a relatively simple 4-way decision, and a linear head on frozen features is the same for every model. Differences therefore reflect only feature quality, and the feature dimension (768 for ViT up to 2048 for ResNet-50) showed no clear relationship with accuracy.

  • Input requirements: all models take 224x224 crops. Because the frames are 16:9 (854x480), the center crop discards the left and right edges, so characters near the sides can be lost for every model. This is a shared ceiling on performance and a likely source of errors for the both and neither classes in particular.

  • Domain shift: the models were pre-trained on natural photographs, not cartoons, so none of them has seen this visual style. This helps explain why accuracy plateaus in the low-to-mid 80s for all five.

Limitations¶

  • Timing is only rough. The ms/image figures include JPEG decoding and preprocessing on the CPU (single process), not just the network’s forward pass, and ResNet-50 ran first and so includes GPU warm-up. The ResNet-50 time (18.0 ms) is therefore inflated and the speed ranking should not be read as a pure architecture comparison.

  • Backbones were frozen and only a linear head was trained, so the results measure how well ImageNet features transfer, not each architecture’s ceiling.

  • Consecutive frames from the same scene are near-duplicates, so a random split may put almost identical images in train and test and overestimate accuracy.

  • A single split and a single seed were used, so the small gaps between models are not statistically significant.

10. Conclusion¶

Using frozen ImageNet features with a simple linear head, all five torchvision models classified Tom & Jerry frames with 82.7-84.9% accuracy. ViT-B/16 performed best (accuracy 0.849, macro-F1 0.843), but at 86.6M parameters it is far larger than the alternatives and only about 2 points ahead, a gap within the margin of error for this test set. DenseNet-121 offers the best balance of accuracy and size (macro-F1 0.831 with only 8.0M parameters, ahead of the larger ResNet-50), while MobileNetV3-Large is the fastest and smallest-footprint choice, giving up only about 2 points of macro-F1 compared with ViT-B/16. For all models, the both class and the small character Jerry were the main sources of error, and the center-crop preprocessing probably contributed.

Recommended next steps: fine-tune the last blocks of the best backbone, feed the full 16:9 frame (or resize without cropping) so edge characters are not lost, add augmentation, split by scene/episode to remove near-duplicate leakage, and consider a multi-label formulation (Tom present? Jerry present?) with a sigmoid head.
